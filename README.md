# 人事資料建檔及更新_資訊填寫 — 部署說明

## 架構
- `index.html`：前端，放 GitHub Pages（公開）。**不含任何員工資料。**
- `Code.gs`：後端，Google Apps Script，綁定一份 Google 試算表。員工名冊與填寫資料都只存在試算表。

## 一、建立試算表與後端（約 10 分鐘）
1. 建立新的 Google 試算表，第一個工作表改名為 `員工名冊`，欄位為 `工號 | 姓名 | 部門`（可直接貼上你的員工附件內容，範本見 `員工名冊_範本.csv`）。
   - 工號欄請先設為「純文字」格式，避免開頭 0 被吃掉。
2. 試算表選單 → 擴充功能 → Apps Script，貼上 `Code.gs` 全部內容並儲存。
3. 專案設定 → 指令碼屬性 → 新增 `ADMIN_PASSWORD`，值為人資管理密碼（黃寶蓮進入管理頁時輸入）。
4. 部署 → 新增部署作業 → 類型「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 首次部署時需授權（寄信、Gmail 讀取退信、試算表）。
5. 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。
6. 之後若修改 `Code.gs`，要「管理部署作業 → 編輯 → 新版本」才會生效。

## 二、發佈到 GitHub Pages
1. 開啟 `index.html`，把最上方 `CONFIG.API_URL` 換成步驟 5 的網址。
2. 建立 GitHub repo（可為 public），上傳 `index.html`（可命名為 `index.html` 直接當首頁）。
3. Settings → Pages → Branch 選 `main` / root → 儲存，取得 `https://<帳號>.github.io/<repo>/`，把連結發給員工。

## 功能對照
| 需求 | 實作 |
|---|---|
| 工號自動帶入姓名、部門 | 後端查「員工名冊」 |
| 查無工號可新建 | 勾選「新建」後自行輸入姓名、部門（資料標記為「自建」） |
| 送出 / 更新 | 已有資料時按鈕自動變「更新」 |
| 空白欄位提醒、不可送出 | 前後端雙重檢查，並標紅欄位 |
| 個人MAIL 備註 | 欄位下方警示文字 |
| 人資管理（7003001） | 需再輸入管理密碼；全部 / 已填 / 未填 / MAIL 未確認篩選、搜尋、匯出 CSV |
| 員工MAIL測試 | 見下方 |
| 不知道工號 | 首頁「姓名」欄直接輸入姓名（至少 2 字）自動查出工號與部門；同名者列出部門讓本人點選 |
| 無法驗證MAIL | 填寫頁可勾選「暫時跳過驗證」，資料照常送出，MAIL 狀態標註為「未驗證」，之後由人資寄測試信確認 |

## MAIL 測試的做法（建議）
單純「寄信看有沒有退信」無法證明本人收得到，所以用兩層：
1. **員工填寫時：驗證碼驗證（必要）**。按「寄送驗證碼」，系統寄 6 位數碼到該信箱，輸入正確才能送出。能送出的 MAIL 一定是收得到的。
2. **人資管理：測試信 + 確認連結**。對已填者（或全部「未確認」者）寄確認信，員工點信中連結後狀態變「已驗證」；另有「檢查退信」，掃描 Gmail 內的退信通知並標示「退信」。適用於舊資料或日後修改 MAIL 後的複查。

狀態說明：已驗證 / 未驗證（員工選擇跳過）/ 待確認（已寄測試信尚未點擊）/ 退信 / 未填。
管理頁的「MAIL 未確認」篩選與「寄給所有未確認者」，會涵蓋「未驗證」「待確認」「退信」三種狀態。

## 設定指令碼屬性
- `ADMIN_PASSWORD`：人資管理密碼（必填）
- `FRONT_URL`：GitHub Pages 網址，結尾加斜線，測試信的確認連結會指向這裡（建議設定）

## 注意事項
- **寄信額度**：一般 Gmail 帳號每日約 100 封，Google Workspace 約 1500 封。全公司測試信請分批寄，管理頁會顯示剩餘額度。
- **身分確認**：員工端只靠工號登入，知道別人工號就能改別人的資料。MAIL 驗證碼能降低亂填，但不能完全防止冒名。若要更嚴謹，可加上「身分證後四碼」或「生日」等第二欄位（需在名冊增加欄位）。
- **個資**：手機、地址、MAIL 只存在你的 Google 試算表，請限制試算表的共用對象；GitHub 上不要放名冊。
- 管理密碼存在指令碼屬性，不在前端程式碼中。
